# Writing Rules for This Project

## Anti-AI Writing — Professional Copy

When editing or generating resume bullets, professional summaries, project descriptions, or any human-facing copy in this portfolio, strictly follow these rules:

### Banned Phrases & Patterns

- **No AI-tell verbs:** Do not use "Leveraged", "Architected", "Spearheaded", "Orchestrated", "Collaborated cross-functionally", "Facilitated", "Championed", "Fostered". Use plain, direct verbs instead (built, wrote, led, ran, fixed, shipped, reviewed, cut, reduced).
- **No em-dashes:** Do not use em-dashes at all. Use a period, comma, or colon instead.
- **No long subordinate clause chains:** Keep sentences short and direct. One idea per sentence.
- **No over-explanation:** Don't add a trailing clause that explains the obvious impact. Concrete facts imply impact.
- **No vague outcomes:** Do not write "improving efficiency", "reducing manual workload", "enhancing performance" without a concrete number or specific before/after context. If there's no real metric, cut the outcome clause entirely.

### Preferred Style

- Short, declarative sentences. Active voice.
- Lead with what was *done*, not what the responsibility *was*.
- Use the candidate's natural register — not more formal than they speak.
- If a bullet is getting long, split it. Do not compress two ideas into one sentence with a semicolon.

### Example

❌ **Before (AI-written):**
> Leveraged AI tooling to orchestrate cross-functional delivery workflows, enhancing team efficiency and reducing manual overhead.

✅ **After (human-written):**
> Used GitHub Copilot and Claude Code to speed up multi-step React changes. Kept code review and architecture decisions manual.
